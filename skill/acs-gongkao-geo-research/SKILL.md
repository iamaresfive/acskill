# 公考机构 GEO 调研

当前版本：`v1.1`

调查中国公务员、事业单位、选调生等公职考试培训机构在生成式 AI、AI 搜索及传统搜索与生成式搜索融合环境中的可发现、可理解、可确认、可召回和可引用能力。

最终目标不是简单罗列搜索结果，而是回答五个问题：

1. 哪些机构能在不含品牌名的真实用户问题中被发现？
2. 搜索系统能否清楚确认机构是谁、在哪里、做什么、由谁提供什么服务？
3. 这些关系只有机构自己陈述，还是存在独立来源交叉确认？
4. 哪些地区、考试、课程、师资或决策问题仍存在可占领的 GEO 空白？
5. 哪些 IP 名师能被自然发现，其与机构、科目、课程和地域的关系是否清楚、稳定且有外部证据？

每项结论都应能回到具体查询、来源网址、证据等级和观察日期。分数是对证据的压缩表达，不得替代证据本身。

## 触发与边界

- 用于地区竞争格局、单机构深挖、多机构比较、机构与 IP 名师实体、GEO 空白词或正式引用报告。
- “哪家教学最好”本身不是 GEO 研究；不要用 GEO 分数回答教学质量、市场份额或真实口碑问题。
- 默认使用“公开网页代理观察”（内部值 `public-web-proxy`）。只有真实采样多个生成式搜索引擎时才增加“多引擎实测”（内部值 `multi-engine sampling`），并与网页代理结果分开报告。
- 报告开头明确：GEO 观察指数不是教学实力排名、市场份额或任何大模型官方推荐榜；未做多引擎实测时不得声称“ChatGPT 真实推荐排名”或“所有 AI 排名”。
- 调查涉及当前公开信息，必须在本次任务重新联网检索；不得根据记忆假装已搜索。

### 四种研究模式

| 模式 | 何时使用 | 必须完成的核心工作 |
| --- | --- | --- |
| 地区全景（内部值 `regional-landscape`） | 用户只给地区，或询问当地整体格局 | 自动调查整个地区的公考机构生态，建立泛词查询题池，发现 10—20 个候选机构及其关联 IP 名师；主报告列出并分析证据充分、排名靠前的机构，另设名师 GEO 分析，其余进入附录或待观察组 |
| 单主体深挖（内部值 `institution-deep-dive`） | 用户指定一个机构、品牌或老师/IP | 只调查该指定主体，完成实体图谱、泛词表现、外部验证和空白分析；指定机构时同步调查其可核验的关联 IP 名师，除非用户另行要求，不自动补充其他机构 |
| 多主体比较（内部值 `institution-comparison`） | 用户指定两个及以上主体进行比较 | 只比较用户点名的全部主体，使用统一题池、窗口和评分口径；机构比较中同步比较各机构可核验的 IP 名师 GEO，不新增未点名机构 |
| 空白机会分析（内部值 `gap-analysis`） | 用户询问空白词、机会问题或概念占位 | 从无结果、弱结果、实体歧义和概念归属不稳的真实查询生成分级机会地图 |

若请求同时涉及多个模式，以用户最关心的问题为主模式，其他模式作为子任务。例如“比较三家机构并找广东空白词”以多主体比较为主，同时输出机会地图。

## 开始前必问

在任何联网搜索或评分前，先用一条简短消息完成以下问询：

```text
开始前请确认：
1. 要调查哪个省、市或区域的公考机构 GEO 排名？
2. 是否需要把您自己的机构强制纳入本次报告？如需要，请提供准确的对外名称；可同时提供简称、曾用名或官网，便于实体核验。
```

- 用户已在当前请求中明确区域时，不重复询问第一项，只复述已识别区域并询问第二项。
- 用户回答“不需要”后，按纯地区模式自动发现、排名和分析。
- 用户回答“需要”但未给机构名时，只追问准确机构名称；名称确认前不开始搜索，不从账号资料、历史对话或记忆中猜测。
- 用户要求在地区排名中加入自有机构时，仍使用地区全景模式：继续调查整个地区，同时把该机构作为内部“用户指定”样本强制纳入评分和重点分析。即使泛词查询未发现它，也不得从报告删除。
- 强制纳入不等于加分。其泛词命中为零时如实记录，并解释“未被本次泛词样本发现”不等于机构不存在、经营失败或教学能力弱。
- 地区报告默认调查机构关联的 IP 名师，不再额外询问是否开启。用户选择纳入自有机构时，可自愿补充该机构希望核验的老师姓名或账号；未提供时由公开证据发现，但不得猜测人物归属。
- 如果用户明确要求的不是地区排名，而是单独调查一个或多个点名机构，则进入指定机构模式，只调查点名集合。

### 不应触发或应改道的请求

- 只问公告、大纲、招录人数、考试时间或题型题量：使用公考考情检索能力，不启动 GEO 评分。
- 只问某机构教学质量、师资水平、退费纠纷、真实口碑或市场份额：说明 GEO 证据不能回答这些问题，转为相应事实调查。
- 只要求撰写品牌宣传、搜索优化文章或投放文案：不是本 Skill 的研究任务。
- 用户把“GEO 排名”等同“教学最好”时，先纠正口径，再决定是否继续做可见性研究。

## 解析请求

提取并记录：

| 字段 | 识别内容 | 默认与处理规则 |
| --- | --- | --- |
| `region` | 省、城市、都市圈或跨区域范围 | 缺失但机构地域明确时先从可靠来源核验；无法确定且会改变题池时询问用户 |
| `cities` | 核心城市、地级市或独立招录城市 | 省域任务根据当地考试生态选择，不默认只看省会 |
| `include_owned_institution` | 是否在地区排名中强制纳入使用者自己的机构 | 地区调查开始前必须询问；默认不猜测，等待用户回答“需要 / 不需要” |
| `owned_institution_names` | 自有机构准确名称、简称、曾用名或官网 | 仅在用户选择纳入时收集；至少确认准确对外名称 |
| `owned_teacher_names` | 自有机构希望核验的 IP 名师姓名、别名或账号 | 可选；未提供不阻塞调查，由公开证据发现并核验人物关系 |
| `institution_names` | 单独指定调查的机构、品牌、老师/IP，可为零个、一个或多个 | 只认用户当前请求中明确点名的主体。纯指定机构请求只调查这些主体，除非用户明确要求增加对标；不要与地区排名中的“强制纳入自有机构”混淆 |
| `research_scope` | 四种研究模式之一 | 未指定时按上表自动判断 |
| `query_depth` | 快速、标准、深入、完整（内部值分别为 `quick`、`standard`、`deep`、`full`） | 默认标准档约 20 个问题；依次对应约 10、20、50、100 个实际采样问题 |
| `output_format` | HTML、完整运行目录或图表 | 默认直接生成并交付完整的 `report.html`；不得只交 Markdown 或 CSV。用户明确指定其他格式时按其要求执行 |
| `observation_date` | 实际采样日期 | 必须使用本次调查日期，不使用 Skill 创建日期或旧报告日期 |

用户说“深度”“完整”“详细”时至少使用深入档；明确说“100 个问题”或“全量题池”时使用完整档。用户指定问题数时以用户数量为准，同时保持各类问题的合理覆盖。

```text
研究模式：
地区与城市：
指定主体：
是否强制纳入自有机构：
自有机构名称：
自动发现/对标规则：
查询深度与预计问题数：
采样模式：public-web-proxy / multi-engine sampling
IP名师调查：开启
观察日期：
交付格式：
已知限制：
```

缺失信息若不影响方向，可以采用明确默认值继续；若会改变地区、指定机构、研究模式或真实采样范围，则用一个最小问题向用户确认，不猜测。

### 地区和候选主体规则

- 只有地区时，先识别当地主要城市、独立招录体系、主要考试及真实笔面试生态，再地区化题池；不得把某省专属词机械复制到其他省份。
- 未给机构名单时，固定使用地区全景模式：以整个目标地区为调查对象，用泛词查询自动发现 10—20 个有证据的主体，覆盖全国品牌、本土综合机构、细分机构、老师/IP 型品牌和近期新主体；完成评分后，在主报告列出并重点分析排名靠前且证据达到可解释门槛的 5—10 家。
- 地区模式下不得因为委托方身份、用户画像、历史对话、记忆或研究者偏好，擅自加入某个机构、老师/IP 或所谓“自有主体”。只有用户在前置问询中明确选择纳入并提供名称，才将该机构记为 `Specified`；用户选择不纳入时，`Specified` 必须为零。
- 地区排名中强制纳入自有机构不会关闭候选自动发现：报告仍调查整个地区并按统一口径排名，同时确保该机构进入评分和重点分析。
- 用户发起纯单机构或多机构调查时，才关闭地区候选自动发现，只调查用户点名的集合。点名主体不得因分数低而删除；除非用户再次明确要求增加对标，否则不得加入任何其他机构。
- 主报告聚焦领先机构及其差异、证据、模式与优化机会；未达到证据门槛的主体不凑精确排名，统一进入“待观察”附录并说明缺口。
- 证据弱者标为“证据不足 / 待观察”，不为凑数量建立精确分数。
- 单机构和多机构指定模式都不自动增加对标。只有用户明确说“增加对标、补充竞品或与地区领先者比较”时，才可新增主体；新增者必须标记 `Benchmark` 并解释选择理由。
- 名称相近、品牌与公司主体不一致、老师/IP 与机构关系不明时，先建立别名和待核关系，不提前合并实体。
- 地区模式须从师资类泛词查询、机构页面、老师实名账号和外部来源中发现 IP 名师。每个主报告机构至少核验其核心老师线索；存在稳定公开身份的名师时，记录姓名／别名、所属或合作机构、主讲科目、代表课程、地域关联、内容平台、泛词命中、品牌词命中、概念占位和外部引用。
- “IP 名师”不是主观称号。只有人物身份可确认，并存在持续内容、科目／产品关联或跨来源提及时，才进入名师分析表；证据不足者放入待核名单。
- 名师 GEO 作为机构 GEO 的解释层单独展示，不与机构混在同一排名表。粉丝量、播放量或老师知名度不得直接给机构加分；只有形成可核验的“机构—老师—科目—课程—地域”关系时，才按既有规则影响实体清晰度、概念占位度或内容新鲜度。
- `Candidate`、`Specified`、`Benchmark` 只表示样本如何进入调研：分别为地区查询发现、用户指定、用户明确要求后补充的对标；它们不是机构等级、经营身份或优劣判断，也不得影响评分。
- `role` 保留在 `scores.csv` 供审计。最终报告主排名表默认不展示原始英文 `role`；确有解释需要时，在方法或附录使用“入选方式”，并映射为“调研发现 / 用户指定 / 对标补充”。

## 执行流程

按证据驱动顺序执行，不先定排名再找材料。下面 20 步是完整流程；快速档可以减少问题数和主体数，但不能跳过证据分级、泛词／品牌词分离、IP 名师核验、置信度和免责声明。

1. 解析研究范围
2. 确定地区与考试生态
3. 建立泛词查询矩阵
4. 发现候选机构与 IP 名师
5. 执行泛词查询
6. 执行品牌与实体查询
7. 识别官方来源
8. 收集独立来源
9. 对域名与文章去重
10. 评定证据等级
11. 建立机构与名师实体图谱
12. 识别概念占位
13. 计算五维分数
14. 评定证据置信度
15. 比较竞争主体
16. 识别 GEO 模式
17. 建立分级机会地图
18. 撰写报告
19. 核验结论
20. 生成证据附录

### 阶段一：确定范围与当地考试生态（步骤 1—2）

1. 输出范围卡，固定研究模式、地区、主体、题量、采样模式、观察日期和交付格式。
2. 从官方或可靠来源核对当地实际考试类型、主要城市、独立招录体系和面试形式。
3. 将未经核实的地区术语标为候选，不直接进入最终题池。

完成标志：地区边界清楚，题池中的考试和面试术语均适用于目标地区。

### 阶段二：建立查询矩阵与候选池（步骤 3—5）

1. 按综合推荐、地域、产品、专项能力、师资名师和决策问题生成泛词查询。
2. 为指定主体、初步候选机构及可核验名师生成品牌词查询，但单独标记，不混入泛词统计。
3. 记录实际执行的问题、时间、渠道和结果；没有执行的问题不计入覆盖率分母。
4. 从泛词查询结果发现候选机构与 IP 名师，并记录“由哪一道问题发现”。

完成标志：`queries.csv` 或等价题池记录完整，至少存在一个泛词查询，候选池与 IP 名师线索的发现依据可追溯。

地区模式的额外完成标志：候选池来自地区泛词调查；主报告的领先机构由同一题池、窗口和评分口径产生；用户选择纳入的自有机构已保留并单独解释自然发现情况，用户选择不纳入时数据中不存在 `Specified`。

### 阶段三：搜索、开源与证据入账（步骤 6—10）

1. 搜索结果页和 AI 摘要只用于发现线索；重要事实必须打开原始页面核验。
2. 优先识别官方主体、政府或主流媒体、独立平台，再补机构官网和稳定内容平台。
3. 每条证据记录机构、查询、标题、网址、域名、发布日期、访问日期、来源等级、是否独立、陈述类型、概念和核验备注。
4. 同一稿件跨站转载只算一个内容源；同域名多篇文章不自动等于来源多样。
5. 机构自述的排名、上岸率、学员数和市场地位必须标为 `institution-claim`，不能改写成独立事实。

完成标志：重点结论都有真实网址，A1/A2/B/C 与自有媒体／外部自然引用已区分，重复稿件已标记。

### 阶段四：建立实体图谱与概念占位（步骤 11—12）

逐家机构及其关联 IP 名师回答：

- 品牌与公司/组织主体是否清楚？
- 创始人、老师/IP 与机构关系是否可确认？
- 科目、考试类型、课程产品、校区/基地和地域是否形成稳定关联？
- 哪些关系仅来自自有媒体，哪些得到外部自然引用确认？
- 哪些概念只偶尔提及，哪些已经在多种问题和独立来源中形成稳定所有权？

关系不确定时使用“疑似关联”“机构自述”“尚无独立来源确认”等限定语，不补全缺失关系。老师离职、兼职、合作或多机构授课必须保留时间和关系边界，不把历史关系写成当前归属。

### 阶段五：评分、置信度与比较（步骤 13—17）

1. 按方法论中的评分锚点逐维打分，每一维先写证据理由，再运行评分脚本。
2. 泛词覆盖度主要由泛词查询支撑；品牌词查询只能补充实体确认。
3. 分数之外独立评定证据置信度，因为高可见性不等于高证据质量。
4. 比较时保持相同地区、题池、采样窗口和来源去重规则；条件不一致时分组展示。
5. 识别 GEO 模式和概念占位后，再从真实弱结果生成分级机会地图。

完成标志：五维分数可复算、等级正确、置信度有依据；地区模式包含自动发现主体及用户明确要求强制纳入的自有机构，纯指定模式只含用户点名主体；用户明确要求对标时，新增对标主体与指定主体已区分。

### 阶段六：成稿、校验与交付（步骤 18—20）

1. 先写核心答案，再给方法、机构榜单／分组、IP 名师分析、竞争格局、逐家分析、模式、机会地图、局限和证据附录。
2. 所有强事实直接附链接或可回溯证据编号；没有证据时降格为待核或分析判断。
3. 运行 `validate_run.py <run-dir> --draft` 检查尚未完成的运行目录；修复错误，逐项人工判断警告，并核对报告中的问题数、证据数、机构数和 IP 名师数与 CSV 一致。`--draft` 只用于中间检查，不得据此宣告完成或向用户交付。
4. 使用 `generate_report_html.py <run-dir>` 从最终 `report.md` 生成自包含的完整 `report.html`，在浏览器中检查中文字体、标题层级、表格横向滚动、来源链接、打印分页、裁切、重叠和黑块。完成检查后运行 `validate_run.py <run-dir> --strict` 做最终文件门禁；该命令默认强制检查 `report.html`，不需要额外参数。
5. 对照用户最初问题逐项确认是否回答，不以文件齐全替代问题闭环。

完成标志：报告写明观察日期、范围、采样模式、证据覆盖和局限；`report.html` 可打开且浏览器检查无版式缺陷；所有文件可打开，脚本无错误。

泛词查询与品牌词查询必须分开。泛问题召回主要计入泛词覆盖度；品牌词只用于确认官网、老师、课程、校区、专业领域和第三方关系，不能替代泛词占位证据。

每个重点机构建立：

```text
品牌 → 公司／组织主体 → 创始人 → 老师／专家
     → 科目 → 考试类型 → 课程／产品 → 校区／基地
     → 城市／区域 → 成绩／案例 → 媒体／平台
     → 外部引用
```

自有媒体与外部自然获得的引用分开统计；同一稿件多站转载只算一个内容源。对事实、机构自述、代理指标和分析推断分别标注。

## 证据表达规范

最终文字中的每项重要陈述必须属于以下一种：

- `来源事实`：来源直接支持，表述不超出原文。
- `机构自述`：由机构、老师或关联账号自行发布，明确归因。
- `代理指标`：本次公开网页或真实引擎采样得到的观察结果，注明时间和样本。
- `分析推断`：基于多条证据形成的解释，写明推断依据和不确定性。

来源等级、软文识别和引用折价以 [source-policy.md](references/source-policy.md) 为准。不得用多篇同源转载制造“多方验证”，也不得用来源数量掩盖来源质量不足。

## 评分、结论与输出

- 用固定五维 100 分模型：泛词覆盖度 30、实体清晰度 25、外部来源多样性 20、概念占位度 15、内容新鲜度 10。
- 使用 `scripts/score_geo.py` 计算总分和等级，不手算后覆盖脚本结果。
- 每家机构同时给“证据置信度：高／中／低”。低置信度或 60 分以下机构之间，不解释 1—2 分或一两个名次的细微差异。
- GEO 模式可多选：品牌权重型、查询铺量型、实体知识图谱型、名师 IP 型、地域实体型、主动 GEO 铺量型；允许按证据新增，不强迫单一归类。
- 机会地图必须从实际查询结果提炼概念占位机会，按 A 优先抢占、B 可系统布局、C 红海分层；不是普通搜索优化关键词堆砌。
- 深度研究保留 `queries.csv`、`evidence.csv`、`scores.csv`、`ip_entities.csv`、`report.md` 和最终交付的 `report.html`；图表为可选。输出字段与目录见数据结构参考。
- 图表仅在数据质量足够时生成，数据必须来自实际评分：GEO 指数横向柱状图、实体可核验性 × 泛词覆盖度象限图。名师分析可增加“机构—名师—科目—概念”关系图，但不得用粉丝量替代 GEO 证据。
- HTML 是默认最终交付件；最终回复直接提供 `report.html`，不得只提供 Markdown、CSV 或让用户自行转换。
- 默认不把研究产物写入任何外部知识库；用户明确要求归档时，遵守目标工作区的 `AGENTS.md`、授权边界和写入规范。

### 五维分数回答什么

| 维度 | 上限 | 核心问题 |
| --- | ---: | --- |
| 泛词覆盖度 | 30 | 不含品牌名的用户问题中，这个机构被发现和提及到什么程度？ |
| 实体清晰度 | 25 | 品牌、主体、人物、科目、产品与地域关系是否清楚、稳定、可核验？ |
| 外部来源多样性 | 20 | 是否有真正独立且多样的外部来源，而非官网自述或同稿转载？ |
| 概念占位度 | 15 | 是否持续与某些地区、考试、课程、老师或方法概念建立稳定关联？ |
| 内容新鲜度 | 10 | 关键实体和内容在当前观察窗口内是否仍然活跃、可访问、未明显过时？ |

分级固定为：S 85—100、A+ 80—84、A 70—79、A- 65—69、B+ 60—64、B 50—59、B- 45—49、C 低于 45。具体评分锚点只在评分时读取 [methodology.md](references/methodology.md)，不要凭印象给分。

### 置信度与排名解释

- 高：核心结论有多类来源交叉支持，实体清楚，泛词样本和独立来源充分。
- 中：主要关系可确认，但地区、题池、独立来源或时间覆盖存在明显缺口。
- 低：主要依赖第一方、品牌词、软文、旧页面或少量样本，只能作初步观察。
- 分数接近但置信度不同，应优先解释证据质量差异，不宣布确定胜负。
- 样本明显不可比时，用“领先组 / 中间组 / 待观察组”或“不足以排名”，不要强排 1—N。

### 交付层级

- 快速档：约 10 个问题，输出范围、代表性发现、证据边界、初步机构组别和下一步；不得伪装成完整榜单，最终生成简版 HTML。
- 标准档：约 20 个问题；只给地区时完成整个地区的机构发现、统一评分、领先机构重点分析、IP 名师分析、竞争格局和证据附录，最终生成 HTML。
- 深入档：约 50 个问题，保留完整运行目录，强化实体图谱、独立来源、逐家分析、IP 名师分析与机会地图，最终生成 HTML。
- 完整档：约 100 个问题，覆盖更多城市、考试、师资和决策场景；必须控制同一观察窗口和去重口径，最终生成 HTML。

无论深度如何，都要明确实际执行的问题数、成功打开的来源数、独立域名数、证据不足的主体数和无法核验的关键事项。

## 标准运行目录与脚本

深度研究按 [data-schema.md](references/data-schema.md) 创建运行目录：

```text
run-dir/
├── queries.csv
├── evidence.csv
├── scores.csv
├── ip_entities.csv    # IP名师与机构关系
├── report.md
├── report.html        # 默认且必需的最终交付
├── geo-index.png     # 可选
└── geo-quadrant.png  # 可选
```

评分输入使用单个 JSON 对象或对象数组：

```bash
python3 scripts/score_geo.py scores-input.json --pretty
python3 scripts/score_geo.py --self-test
```

交付前运行：

```bash
python3 scripts/validate_run.py run-dir --draft
python3 scripts/generate_report_html.py run-dir
python3 scripts/validate_run.py run-dir --strict
python3 scripts/validate_run.py --self-test
python3 scripts/generate_report_html.py --self-test
```

`validate_run.py` 默认要求存在结构完整的 `report.html`。只有报告仍在制作、尚未进入交付阶段时，才可临时使用 `--draft` 跳过 HTML 门禁；草稿校验通过不等于报告完成。

脚本检查结构、字段、分数和部分高风险措辞，但不能替代人工打开网页、确认时间、判断独立性和核对陈述是否被来源支持。

## 禁止事项

- 不捏造机构、网址、来源、检索过程、AI 推荐率或 ChatGPT 推荐率。
- 不因用户点名、品牌搜索结果多或标题写“第一”而提高评分。
- 不把机构官网的上岸率、排名、学员量等自述直接写成客观事实。
- 不把营销软文、聚合转载或搜索摘要当独立权威证据；重要事实打开原始网页核验。
- 不只用品牌词做排名，不以一次搜索声称长期稳定，不混用不同时间窗口而不说明。
- 不为无证据机构凑精确分，不把推测写成确认事实，不把 GEO 指数称为教学实力指数。
- 不把找不到网页直接解释为机构不存在、经营失败或教学能力弱。
- 不因全国品牌规模大而预设其在某地区或某类查询中领先。
- 不把单次观察外推为长期稳定结论；跨期比较必须说明题池、渠道和方法是否一致。
- 不把 Benchmark 混入用户指定机构后伪装成用户原始比较对象。
- 不在指定机构模式下继续自动调查地区领先机构或补充竞品；只有用户明确要求增加对标时才能扩展名单。
- 不根据用户身份、历史对话、记忆或委托关系自动加入机构或老师/IP；只有当前请求明确点名时才使用 `Specified`。
- 不跳过“是否纳入自有机构”的前置问询；用户未确认或未提供准确名称时，不猜测并强行加入。
- 不因自有机构被强制纳入而增加分数、虚构泛词命中或调整排名；其未被发现时如实呈现并分析优化空间。
- 不把 IP 名师的粉丝量、播放量或个人热度直接折算为机构 GEO 分数；不在缺少可靠来源时确认老师与机构的当前关系。
- 不把 `Candidate`、`Specified`、`Benchmark` 当作排名或质量标签；不在面向用户的主排名表中直接展示这些英文内部值。
- 不在未实际访问某个生成式搜索引擎时填写该引擎名称、推荐率或回答结果。
- 不只交 Markdown、CSV 或“请用户自行导出”；默认最终交付必须是完整 HTML。

## 交付前验证

1. 用 `scripts/score_geo.py` 生成或复核 `scores.csv` 对应分数。
2. 制作过程中可用 `scripts/validate_run.py <run-dir> --draft` 检查日期、题池、泛词查询、IP 名师数据、证据、分数、网址、品牌词依赖、低置信度强结论和无来源强事实；不得把草稿校验当作最终门禁。
3. 核对所有事实引用可打开并支持对应陈述；搜索摘要只作发现线索。
4. 核对正文声明的泛词／品牌词问题数、证据数、机构数和 IP 名师数与实际 CSV 完全一致；同一指标在摘要、正文和附录中不得相互矛盾。
5. 检查前置问询已确认区域及是否纳入自有机构；用户选择纳入时，名称、别名与实体核验结果清楚，且该机构未因泛词未命中而被删除。
6. 检查 `Specified` 与用户实际确认对象一致；地区模式中用户选择不纳入时不得出现 `Specified`，选择纳入时仍须保留地区自动发现主体。
7. 若用户发起纯指定机构调查，检查报告和 `scores.csv` 是否只包含点名主体；存在 `Benchmark` 时必须能回溯到用户明确提出的增加对标要求。
8. 检查报告明确观察日期、研究范围、真实采样方式、证据覆盖和局限。
9. 用 `scripts/generate_report_html.py <run-dir>` 生成 `report.html`，在浏览器中检查完整内容、中文字体、表格、链接、横向滚动和打印版式；未通过不得交付。
10. 运行 `scripts/validate_run.py <run-dir> --strict`。只要缺少 `report.html`、存在错误或仍有未处置警告，就不得称完整报告已完成；警告必须人工复核并在交付中说明。

最后人工核对：

- 用户指定的地区和机构是否全部保留；
- 用户只给地区时，是否完成整个地区的机构自动发现，并只对排名靠前且证据充分的机构做重点分析；
- 是否先确认“是否纳入自有机构”，并按用户答案正确保留或排除 `Specified`；
- 用户要求纳入自有机构时，该机构是否在排名和重点分析中保留，同时未获得人为加分；
- 是否错误地根据用户身份、历史上下文或委托关系加入了未点名主体；
- 泛词与品牌词查询是否分开统计；
- 是否调查重点机构关联的 IP 名师，并单独呈现人物身份、机构关系、科目、内容平台、概念占位、自然命中和证据置信度；
- 指定机构模式是否只包含用户点名主体；如有对标，是否由用户明确要求且已标记 `Benchmark`；
- 主排名表是否已隐藏内部英文 `role`，如需说明是否使用中文“入选方式”；
- 每个评分机构是否至少有一条可打开的证据；
- 自有媒体／外部自然引用、事实／自述／代理指标／推断是否分开；
- 榜单、图表和正文使用的分数是否来自同一份 `scores.csv`；
- 机会地图是否来自实际查询缺口，而不是普通搜索优化词表；
- 报告是否明确写出观察日期、采样模式、证据置信度和 GEO 免责声明；
- 报告内各处样本数是否与 `queries.csv`、`evidence.csv`、`scores.csv`、`ip_entities.csv` 一致；
- 最终是否直接交付经过浏览器检查的完整 `report.html`；
- 若只是对话摘要，是否仍提供足够链接让关键结论可复核。
