# 输入与交付格式

用UTF-8 JSON；所有正文为纯文本，不手写HTML。脚本不抓取来源，`access`和`editor_reviewed`只能反映执行者实际阅读及审定，不能因为想通过校验而填写。

## 本期对象

- `brief_date`：`YYYY-MM-DD`，本期用户时区日期。
- `focus`：约200—300字，基于已选卡片的今日焦点；本期少且无足够内容时可短，不能编造补长。
- `keywords`：三个短关键词。
- `search_log`：4—6组`{"direction":"检索方向","queries":["实际检索词"]}`；记录实际做过的检索，不填预设清单冒充执行。
- `previous_review`：近7日去重与衔接结果；未提供历史材料时说明未核范围。
- `corrections`：本期更正的文字数组，无则空数组。需要更正时写清原错及依据；更正来源同时列入相关卡片来源。
- `coverage_note`：条数不足7时必须明确说明原因，任何有来源受阻／材料缺口的期次也如实写；无缺口可为空。
- `editor_reviewed`：人工完成全文证据、判断和引文审阅后才填`true`。
- `cards`：卡片数组，通常7—9条，合格内容不足可0—6条。

## 每条卡片

- `section`：`policy`／`market`／`sentiment`。
- `kind`：policy使用十类性质之一；market用`机构经营`／`资本动作`／`产品师资`／`行业数据`；sentiment用`司法风险`／`投诉维权`／`媒体调查`。纯考务日程不是允许类别。
- `title`、`fact`、`scope`、`verdict`、`reasoning_boundary`：均非空。分别为陈述标题、事实段、适用对象、行业研判及其证据／推理限制。`reasoning_boundary`是审阅辅助，不冒充正式事实。
- `event_date`：事件时间，如`2026-11-01`；原文未交代明确写`未披露`，不能以此绕过来源发布日期。
- `data_period`：涉及财务、人数、比率时写报告期／时点及口径；`机构经营`和`行业数据`类别必填，其他类别按需。
- `document_no`：policy必填，原件确无文号可填`原文无文号`，不得猜。
- `note`：补充口径或缺口，可为空。脚本还会自动展示发布日、事件日、数据期间、证据层级及推理限制。
- `sources`：至少一个`{"publisher":"发布者","title":"原文标题","published":"YYYY-MM-DD","url":"https://...","access":"full_original或full_media","quote":"实际读到的关键短句"}`。首项是主来源；policy首项必须为已读官方原文。来源必须真实可定位，不用搜索结果页、伪造URL或搜索摘要。引文按各来源版权限制缩短，整体衍生篇幅也遵守来源限制。
- `ai_topic`：默认`false`；只有政策事项可为`true`，且须在已读原文中确有相应条款。
- `historical_comparison`：默认`false`；强历史比较为`true`时加`comparison_evidence`，至少三个不同周期，每个`{"cycle":"周期","published":"YYYY-MM-DD","url":"https://...","quote":"对照原文短句","access":"full_original"}`。这是结构门槛，周期可比性与结论仍人工核查。

## 命令与范围

`render`读取已审定JSON，生成`YYYY-MM-DD-公考培训行业动态简报.html`和`YYYY-MM-DD-公考培训行业动态简报-证据.json`。证据JSON保留输入原字节，不是所引网页的完整快照；网页／PDF原件沿本次任务材料保存，有入库授权再按库规归位。目标有同名文件时直接失败，另建版本目录，输入和已有文件不覆盖。

`check HTML --input JSON`做只读检查并与同输入的应有HTML比较，发现改字、漏卡、错链接、日期／计数不一致、HTML注入或禁用标签则非零退出。仅`check HTML`也可检查旧版结构，但不证明其事实及证据链。脚本提示的强因果／历史比较语句需人工复核；不是每个触发词都错，不以全局替换改写原文。

生成后提供HTML入口和简短口头摘要：1—2件重要事项、口径提醒／更正、前期衔接、未核项。没有信息可写空栏目并解释，不产PNG、不设自动任务，不因生成而自动发表或入库。
