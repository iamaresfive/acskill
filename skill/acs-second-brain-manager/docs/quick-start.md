# 5分钟快速开始

## 你只需要先理解一件事

这个 Skill 不会要求你先学知识管理理论。

如果你已经有一个资料文件夹或 Obsidian 知识库，只需要告诉 Agent：

> “用第二大脑知识库管理器管理这个知识库。”

第一次已有库接管默认只读。

## 第一步：告诉它知识库在哪里

例如：

> “我的知识库就是当前这个 Obsidian Vault。”

或者提供本地目录。

Agent 会先确认目录存在、能读取，不会使用别人电脑上的路径。

## 第二步：告诉它这是已有库还是新库

### 已有库

Agent 先看：

- 目录；
- Markdown 页面；
- 是否有 `AGENTS.md` / README / 结构约定；
- 是否有索引；
- 是否用 `[[双链]]`；
- 是否有原始资料区；
- 项目和归档怎么组织。

然后先给你一份“我对这个知识库的理解”。

你确认后才建立治理配置。

### 新库

Agent 会先问你主要拿来管理什么，例如：

- 行业研究；
- 项目；
- 学习；
- 人物与机构；
- 内容创作；
- 咨询案例。

然后给一个最小结构建议。你确认后才创建。

## 第三步：选择写入方式

普通用户直接选默认：

> `confirm-first`

也就是：

> 先看方案 → 你确认 → 再写。

同一个已批准方案内不会每改一个文件都再问一次。

## 以后怎么用

### 查询

> “我以前怎么看加盟模式？”

这是只读，不会写知识库。

### 入库

> “把这份同行交流记录入库。”

Agent 会先判断是更新旧页、合并、创建新页、待核，还是只留原件。

### 更新

> “这个老师现在已经去另一家机构了，更新一下。”

优先改已有实体和关系，不随便新建“最新情况”。

### 体检

> “做一次知识库健康检查。”

默认只报告问题，不自动修。

## 看到 Profile 不用紧张

`profile.yaml` 就是知识库的“设置表”。

你平时不需要手动编辑。

## 看到 Structure Contract 也不用紧张

`structure-contract.md` 就是知识库的“管理制度”。

它告诉 Agent 什么内容放哪里、怎么命名、什么时候新建或更新。

## 最重要的安全规则

- 原始资料默认不改；
- 查询不自动写入；
- 第一次已有库接管不重构；
- 关键冲突不猜；
- 删除、批量移动、改治理规则要单独确认。
