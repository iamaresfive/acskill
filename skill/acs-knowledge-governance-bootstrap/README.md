# 知识库治理初始化与适配 · v1.2.0

**Agent可以换，知识库里积累的东西留下来。**

这个Skill在初始化时，把规范、模板和独立工具安装到知识库，并建立自有Skill的保存、索引和接手规则。以后换Agent，读取库内入口，就能沿用已整理的知识和方法；需要适配的是安装入口、依赖与权限，不用重新整理知识库、重写规范或重做Skill。

使用一次，将适合你的治理方案安装到自己的Markdown或Obsidian知识库。日常工作直接遵循库内AGENTS.md，无需每次调用本Skill。

## 内容放在哪里

| 内容 | 保存方式 |
| --- | --- |
| 知识、来源和业务资料 | 留在知识库，已有库沿用原结构 |
| 规范、模板、独立脚本 | 保存到库内规范与工具目录 |
| 为本库开发或维护的自有Skill | 保存完整正式包，包括SKILL.md及所需脚本、参考、模板和资源；在工具索引登记用途、位置、版本及依赖 |
| Agent里的安装入口 | 引用库内正式包；需要副本时记录来源和版本，更新后同步 |

运行环境、模型和平台内置功能沿用正常安装位置，凭据留在安全存储中。已有Agent目录先盘点、比较和提出方案，不自动搬迁或删除。第三方Skill按来源与许可处理，不把所有已装插件整包复制入库。

安装名为 `acs-knowledge-governance-bootstrap`。

| 场景 | 行为 |
| --- | --- |
| 新库 | 中文目录，按用途选择最小结构，生成规范与工具 |
| 已有库 | 只读理解后映射原结构，补齐或合并治理文件，不搬业务资料 |
| 再次运行 | 相同内容不重复，文件已变化则拒绝覆盖并报告冲突 |

基础包：AGENTS.md、结构约定、知识维护规范、工具与Skill管理规范、工具索引、模板、链接/索引检查、配置与说明。网页、多格式、项目记忆、协作、原件哈希按需选择。附带治理工具只需Python 3.10+标准库；后续自有Skill按各自说明准备依赖。

```text
请使用 acs-knowledge-governance-bootstrap 为这个知识库安装治理方案。
这是已有库，保留目录；先读现有规则并给出具体变更清单，确认后再落地。
规范、模板、独立工具和自有Skill的正式内容要保存在知识库，设计好工具索引和换Agent的接手入口。
```

新库默认目录：

```text
知识库/
├── AGENTS.md
├── 目录.md
├── 知识/
├── 原始材料/
├── 索引/知识全量索引.md
└── 规范与工具/
    ├── 规范/
    ├── 模板/
    └── 工具/
        ├── 工具索引.md
        └── Skill/<skill-name>/  # 有实际自有Skill时保存完整包；已有位置沿用
```

## 换Agent怎么用

让新Agent读取知识库根目录的AGENTS.md，再按任务查看工具索引和相关规范。不会自动发现入口的Agent，显式让它读取这些文件，或在它支持的指令入口中引用。检查库访问、运行依赖和账号授权，再做一次最小读取或调用验证，就可以继续维护已有内容。账号权限和软件能力不会随文件自动迁移。

## 从旧版升级

v1.2.0新增库内工具与Skill管理规范、可持续维护的工具索引，并补充AGENTS接手入口。工具索引在后续升级时保留用户维护的条目。新初始化不会自动导入已有Skill或修改Agent配置。

尚未应用的旧版本方案需重新生成并审阅；已经安装的知识库不自动改写。升级时先查看差异，处理用户修改文件的冲突，再确认安装。原有索引配置保护保留，不自动搬文件或重建原件基线。

不会复制开发者业务、账号或路径，不生成旧式写锁与交接板。用户必须审阅并批准实际安装方案；程序指纹检查是乐观保护，不能替代同文件修改协调。
