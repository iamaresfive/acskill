# 知识库治理初始化与适配 · v1.4.0

**Agent可以换，知识库里积累的东西留下来。**

这个Skill在初始化时，把规范、模板和独立工具安装到知识库，并建立自有Skill的保存、索引和接手规则。以后换Agent，读取库内入口，就能沿用已整理的知识和方法；需要适配的是安装入口、依赖与权限，不用重新整理知识库、重写规范或重做Skill。

使用一次，将适合你的治理方案安装到自己的Markdown或Obsidian知识库。日常工作直接遵循库内AGENTS.md，无需每次调用本Skill。

## 内容放在哪里

| 内容 | 保存方式 |
| --- | --- |
| 知识、来源和业务资料 | 留在知识库，已有库沿用原结构 |
| 规范、模板、独立脚本 | 保存到库内规范与工具目录 |
| 为本库开发或维护的自有Skill | 保存完整正式包，包括SKILL.md及所需脚本、参考、模板和资源；在工具索引登记用途、位置、版本及依赖 |
| Agent里的安装入口 | 引用库内正式包；需要副本时记录来源和版本，更新后同步 |

运行环境、模型和平台内置功能沿用正常安装位置，凭据留在安全存储中。已有Agent目录先盘点、比较和提出方案，不自动搬迁或删除。第三方Skill按来源与许可处理，不把所有已装插件整包复制入库。

安装名为 `acs-knowledge-governance-bootstrap`。

| 场景 | 行为 |
| --- | --- |
| 新库 | 中文目录，按用途选择最小结构，生成规范与工具 |
| 已有库 | 默认保留原结构；旧文件是否按新规范迁移可单独选择，获批后由Agent执行 |
| 再次运行 | 相同内容不重复，文件已变化则拒绝覆盖并报告冲突 |

基础包：AGENTS.md、结构约定、知识维护规范、工具与Skill管理规范、工具索引、模板、链接/索引检查、配置与说明。网页、多格式、项目记忆、协作、原件哈希、工作文件分类与交接中转站按需选择。附带治理工具只需Python 3.10+标准库；后续自有Skill按各自说明准备依赖。

```text
请使用 acs-knowledge-governance-bootstrap 为这个知识库安装治理方案。
这是已有库，保留目录；先读现有规则并给出具体变更清单，确认后再落地。
规范、模板、独立工具和自有Skill的正式内容要保存在知识库，设计好工具索引和换Agent的接手入口。
```

新库默认目录：

```text
知识库/
├── AGENTS.md
├── 目录.md
├── 知识/
├── 原始材料/
├── 索引/知识全量索引.md
└── 规范与工具/
    ├── 规范/
    ├── 模板/
    └── 工具/
        ├── 工具索引.md
        └── Skill/<skill-name>/  # 有实际自有Skill时保存完整包；已有位置沿用
```

## 两个可选模块

| 模块 | 你可以怎么选 | 实际作用 |
| --- | --- | --- |
| 工作文件分类 | 不启用／沿用现有／采用推荐／自定义 | 约定AI成果保存位置、用途分类、是否按软件分目录 |
| 交接中转站 | 不启用／指定独立目录 | 不同软件或窗口间交接任务、附件与剩余事项，也可直接转贴 |

两项默认关闭，互不依赖。推荐分类为文档报告、表格数据、图片设计、音视频、代码工具、资料整理，每项任务再按日期与主题集中存放；可删减或改名。

Agent通过对话补齐选择并生成配置，无需你写JSON。安装只保存规则与路径，实际文件夹在任务需要时创建；不会搬旧文件、自动入库或清理中转站。换软件还要核对权限，不提供自动跨设备同步。

## 旧文件是否迁移

旧文件迁移是另一个独立选项：**暂不迁移（默认）／迁移指定范围**。不迁移也能启用新规范，旧文件保留原位，新产出按新规范存放。选迁移时，Agent先提供原位置到新位置的完整方案，说明冲突及影响；你同意后，它实际搬迁、修复索引与链接、核对文件完整性。初始化脚本本身不搬文件，具体执行需Agent具备对应文件权限。见[迁移流程](references/migration.md)。

## 换Agent怎么用

让新Agent读取知识库根目录的AGENTS.md，再按任务查看工具索引和相关规范。不会自动发现入口的Agent，显式让它读取这些文件，或在它支持的指令入口中引用。检查库访问、运行依赖和账号授权，再做一次最小读取或调用验证，就可以继续维护已有内容。账号权限和软件能力不会随文件自动迁移。

## 从旧版升级

v1.4.0增加可选的历史文件迁移流程：明确选择、审批具体映射，再由Agent实际执行与验收；默认不迁移，保留现状不阻塞新规则启用。迁移规范随基础包落地，启用规则不自动触发迁移。

v1.3.1明确四项适配检查：知识库管理、工作文件夹、工作产出、中转站。与已有约定冲突时，Agent须说明原规则、整改方案和影响，经你明确同意后才修改。还须核对你的Agent是否实际读取规则；文件保存完成不等于已在所有软件里生效。

v1.3.0新增两个可选工作模块，支持在原映射不变时按审阅方案增加模块；补强入库质量、旧观点更新、方法沉淀、所有Agent按任务授权与分范围验收。v1.2已有的工具索引和自有Skill包保留。移除模块、改变旧路径或布局仍需单独迁移方案，安装器不自动删除旧规则。

尚未应用的旧版本方案需重新生成并审阅；已经安装的知识库不自动改写。升级时先查看差异，处理用户修改文件的冲突，再确认安装。原有索引配置保护保留，不自动搬文件或重建原件基线。

不会复制开发者业务、账号或路径，不生成旧式写锁与交接板。用户必须审阅并批准实际安装方案；程序指纹检查是乐观保护，不能替代同文件修改协调。
