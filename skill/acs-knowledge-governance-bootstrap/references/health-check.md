# 验收范围

安装后直接运行目标库工具目录下的治理检查.py，不需要原Skill或PyYAML。工具检查本地Wiki和普通Markdown文件链接，以及配置full_index中的知识页遗漏/重复；只支持链接式索引，其他索引形式人工验收或先适配，不擅自改格式。

文件名重复、歧义链接和断链均需审查。无frontmatter、孤立页仅为信号，不自动建页或补链。工具不验证事实真实性、标题锚点、引用式链接、远程网站或语义关系。

基础包包含库内工具与Skill管理规范及工具索引。自动链接检查会检查索引到Skill入口文件的链接；默认 `工具/Skill/` 内的正文按独立包处理，不扫描其示例、约定格式或重复的SKILL.md文件名。它不会发现库外漏存的包、检查包内依赖是否完整或证明Skill可运行；已有自定义包位置需要按既有工具适配检查范围。

人工验收还要核对正式包、版本、来源、依赖和Agent安装入口的关系。隔离复制知识库后，离开原初始化包运行治理检查，验证库内工具独立；有自有Skill时再做无外部副作用的最小操作。换Agent需要的凭据与运行环境列明，不随库复制。保留用户维护的工具索引和正式包，不能为通过检查重建成空模板。

选择source-hashes模块后独立运行原件校验：prepare生成库外候选，人工核对新增文件，commit复验候选与旧基线，check独立全量比较。已有原件改变或丢失时禁止提交新基线。此为完整性校验，不证明来源事实正确，也不是原子并发锁。

初次安装前后各做必要范围核验，区分旧问题和新引入问题；不要为清零旧库警告而顺手修改无关知识页。未完成项明确列出，不能把工具exit 0当作完整治理验收。

## 日常按改动范围验收

- 仅修错字、说明或格式且不改变规则行为：核对全部差异和涉及链接，不因几个字重跑整库。
- 更新知识正文：检查受影响页、来源语义、必要索引与直接引用；完成不等于全库健康。
- 增加原始材料：若启用哈希模块，仍独立全量校验原件，不用正文局部检查代替。
- 改目录、权限、流程、模板、工具或启停模块：检查治理入口及受影响消费者，运行库内治理检查；代码变更验证实际行为。

这是验收选择规则，不是新命令；附带治理检查.py仍只提供所声明的链接与索引检查。已有库沿用自己的验收工具，不虚构format/content等参数。通过后无新变更或失败不重复同等级检查。

work-files和handoff模块的库外路径只记录，不由安装器创建、扫描或迁移。验收核对生成的规范、模板、入口和配置是否对应用户选择；未启用时不生成相关文件。能读到路径不等于跨设备可访问，首次实际使用另核对环境。
