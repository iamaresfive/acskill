# 工作文件管理

仅在用户选择工作文件模块时采用。本文件上方记录用户确认的位置和布局，不套用作者的电脑路径或业务分类。

## 三种选择

- `existing`：沿用已有布局，记录明确的目录约定，不添加另一套分类。
- `recommended`：推荐“软件（可选）／主要用途／YYYY-MM-DD-任务主题”。六类起点为文档报告、表格数据、图片设计、音视频、代码工具、资料整理；可由用户调整。
- `custom`：用户选择是否按软件分目录、分类名称与特殊约定。Agent通过对话补齐选择并生成配置，不要求用户填写JSON。

推荐形态为 `<工作根目录>/<软件名>/<分类>/YYYY-MM-DD-任务主题/`。关闭按软件分类后省去软件名这一层。同软件换模型或新建聊天沿用目录；只有实际任务需要时才创建相应分类和任务文件夹。

## 保存与查找

1. 当前任务指定位置、已确认业务专用目录优先，仓库代码留在对应仓库。
2. 按任务主要用途选一个分类。正文、配图、附件、脚本和依赖集中保存，不按扩展名拆散。例如图文发布包整体归文档报告。
3. 临时缓存可用系统临时目录；需后续保留或交付的成果归任务目录。新版本另命名，已有目标先核对，不覆盖别的任务成果。
4. 工具调用显式指定实际输出路径，交付给出可打开的路径。目录约定不代表各Agent已自动加载，要确认该Agent能读规范、访问路径。
5. 工作成果不自动成为知识。入库仍按授权和查重合并规则处理，不将工作根目录全部纳入知识索引或原件哈希范围。
6. 中转站若位于工作根目录内，作为独立交接区排除出成果分类，不把其材料自动整理到某个软件名下。

## 已有文件与环境

本次启用不搬迁旧文件、不修改其他软件配置、不自动清理。不为统一目录移动应用、模型、运行环境或凭据。

另获迁移授权后，先列源路径、目标路径与冲突，整包保留相对依赖，以不覆盖方式迁移；核对文件清单、大小、哈希和实际入口。未完成部分保留并说明，历史原件不为修路径改写。

本机路径只适用于已核对的机器。云端Agent按其可用环境交付，不能建立同名路径就宣称已存到用户电脑。换机器重新适配外部路径，未经授权不自动同步或上传。
