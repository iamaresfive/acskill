# 工具与Skill管理规范

## 正式内容留在知识库

知识库应能由不同Agent接手。知识、来源、规范、模板、脚本和为本库开发或维护的自有Skill，不能只保存在某个Agent的安装目录、会话或记忆里。适用于本库且需要复用的内容，经用户授权后沉淀到库内；临时缓存不必归档。

- 规范、模板和独立脚本沿用本库结构。
- 自有Skill的正式包默认放在治理工具目录的 `Skill/<skill-name>/`；已有等价位置时沿用，并在库内工具索引写明实际位置。没有Skill时不创建空包。
- 保存完整包：`SKILL.md` 及它实际依赖的脚本、参考、模板和资源；保留相对路径。不只摘存说明，不把包内资源拆到不同Agent目录。
- 工具索引登记用途、入口、版本或来源、运行依赖及接入方式；外部依赖和安装方式写进包内说明，不能只留在聊天中。
- 第三方Skill保留来源、版本和许可；确认允许保存和使用后再归档。平台内置能力、模型、运行环境和凭据沿用其正常位置，不把软件安装目录整包复制入库。

## 库内版本统一维护

Agent安装目录用于发现和调用。支持链接或路径引用时指向库内正式包；只能安装副本时，记录来源和版本，更新库内正式包后同步副本并核对差异。不要在多个安装副本中各自维护，也不让两个执行者同时改同一正式包。

对既有Agent目录先只读盘点：核对哪些是用户自有、哪些已有库内版本、是否有版本差异，再列出保存、合并与接入方案。未获授权不搬迁、删除或替换现有包，不因为库内缺失就覆盖Agent中较新的版本。外部入口若有绝对路径，库移动后单独重新适配；包内文件尽量使用相对路径。

## 换Agent时怎样接手

1. 让新Agent读取根目录 `AGENTS.md`、结构约定和本规范，再按任务读取工具索引与相关包。
2. 检查能否访问库、所需解释器或外部服务是否可用。不会自动读取AGENTS或发现Skill时，在该Agent支持的指令入口中引用库内文件，或明确让它读取。
3. 需要时适配安装入口、机器路径、依赖和账号授权。配置位置及参数含义可记录在库内；密钥、令牌和登录态留在安全存储中。
4. 选一个与任务相关、无外部副作用的最小操作验证读取和调用；回读已有资料，确认可继续维护。无法运行的依赖明确列出，不能只看到文件就说接手完成。

换Agent应复用已经沉淀的内容，只适配运行入口和环境；不要求重新整理知识库、重写规范或重做Skill。Agent切换本身不授予写库或外部操作权限。
