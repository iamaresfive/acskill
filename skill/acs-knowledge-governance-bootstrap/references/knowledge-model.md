# 知识模型、检索与写入规则

## 1. Source 与 Knowledge

原始材料层用于证据保真；知识层用于持续维护当前认知。

已有原始材料默认不可改写。知识页可更新，但必须保持来源可追溯。

## 2. 五种写入决策

### UPDATE

当新信息明确替代旧状态时更新已有知识。

### MERGE

当新信息属于已有主题时融入现有模块，避免“补充1/补充2/最新版”碎片。

### CREATE

仅在需要新的稳定知识节点时创建。

### PENDING

身份、金额、日期、归属、关键结论冲突无法核实时，不猜测。

### SOURCE_ONLY

原件有保留价值，但暂不产生新的知识节点。

## 3. Retrieval Policy

检索遵循由窄到宽：

1. 文件名/标题/别名；
2. 已知实体或项目入口；
3. 相关章节；
4. 来源和真实关联页；
5. 更广的语义搜索；
6. 只有全库审计才全量扫描。

回答必须读取足够上下文，不用孤立命中行替代结论。

查询不会自动更新知识库。

## 4. Mutation Plan

写入前至少回答：

- 输入源是什么；
- 已有相关页是什么；
- 是否存在重复或实体歧义；
- 五种决策中的哪一种；
- 旧结论是否被覆盖；
- 是否有 Pending；
- 来源放哪里；
- 是否影响关系、索引、项目状态；
- 是否触及治理变更。

## 5. 事实边界

每个关键结论必须能区分 Source Fact / User Judgment / Agent Inference / Decision / Pending。

## 6. 页面类型

已有体系优先。没有时可使用：entity、concept、source-summary、comparison、synthesis、case、procedure、tracker。

页面 type 不决定物理目录。

## 7. 关系

关系必须真实、稳定、对导航或理解有价值。不以“链接越多越好”为目标。

## 8. Entity Resolution

短别名、常见人名、品牌名与公司名都可能冲突。只有证据足够时合并；否则保留待核或 Merge Proposal。

## 9. Snapshot

时效数据必须有观察日期/统计期间。`updated` 不能替代数据时间。

长期方法和当期数据分离，同口径多期后再描述趋势。

## 10. 项目

不得按日期自动判断结束。项目状态应由用户、明确字段或已确认规则决定。

## 11. 入库质量与增量更新

- 先判断是否有决策、执行、复用或追溯价值。重复材料和制作中间稿不机械入库；有追溯价值但无新结论可只存原件。
- AI会议总结、自动摘要属于派生材料，不能为自身推断作证；关键结论回查逐字稿或原始上下文。分清提出方向、确认方案、实际执行、验证效果，不能因整理或反复提及升级状态。
- 用户口述和粘贴文本保留真实原始副本再提炼。已保存的确认摘存也属原件；后续改变另存新来源，不向旧原件追加。
- 跨章节重组读完整目标页和相关来源；局部补充读完整相关章节与来源上下文，并检索全页冲突。执行指令全文读取，不靠孤立命中行修改规则。
- 已明确替代的旧口径退出当前正文，历史留在原件与日志；未裁决冲突标待定，不擅自选边。新建议融入主题，不按Agent、日期或轮次堆叠“补充”。
- 写后检查整页重复、层级、编号、状态和阅读顺序。回报哪些旧内容被替代、合并、保留待定或仅存原件。

## 12. 从案例到方法

方法可来自经营、管理、服务、学习或创作。先保留案例和来源，再提炼问题、依据、适用条件与验证情况；一次成功不自动成为通用规律。沿已有主题归位，必要时提供导航，不另建重复事实库。

遇到新事实、用户修正或实践反例，核对原主档：事实变化更新事实，适用条件不同说明范围，未裁决观点保留待定。旧原话、已发布版本和来源快照保持原样。过期提醒放在具体结论旁，注明观察截止或“引用前核实”，不因局部过期宣告整页失效。

## 13. 授权与完成

所有Agent默认读取分析，写入依当前任务授权。完整方案获批后连续完成范围内来源、正文、必要索引与记录、适用验收，不逐文件重复确认；新批次或改变边界再确认变化部分。关键身份、金额、日期或结论待核时，仅暂停依赖该疑点的写入，其余独立且已授权部分继续。

仅复制文件或脚本通过不叫入库完成。核对来源链、正文可用性、必要入口和实际检查结果，未完成项如实说明，不另加一套验收台账。已有日志沿用并按批次追加；无日志时按目标库约定说明结果，不自动补建。
