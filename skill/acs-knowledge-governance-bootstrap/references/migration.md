# 可选：旧文件按新规范迁移

本流程由具备文件操作能力的Agent在具体授权下执行；bootstrap.py只安装规则，不执行历史搬迁。没有本机或目标存储访问能力时说明限制，不把建议清单当成已迁移。

## 独立选择，默认不迁移

先询问尚未明确的选择：“旧文件是否按新规范迁移？”

- **暂不迁移（默认）**：保持旧文件及路径，约定的生效点之后新产出按新规范保存；旧资料沿原入口查找。新规则若与旧目录不兼容，明确新旧并存范围，不能让新索引遗漏旧资料。该选择不阻塞新规范启用，以后可再迁。
- **迁移指定范围**：用户选定知识库、工作文件夹、历史产出或中转站中的具体范围，再盘点并准备方案。不能推定所有文件、整台电脑或所有Agent目录都在范围内。

同意新规范、安装Skill、选择工作分类或中转站，均不代表同意迁移。用户已经明确选过的不重复问；同意迁移方向后，仍须看到并批准具体方案，不能先搬再展示。

## 先给出可审阅方案

1. 只读盘点选定范围，读取原规则。识别整项任务的正文、附件、图片、脚本及相对依赖；原始材料、运行环境、凭据、应用数据和其他任务中的文件单独标明边界。原件内容不可改写，不以归类名义去重、合并或删内容。
2. 在库外准备逐项“源路径 → 目标路径”映射和保留清单，记录文件数、大小、SHA-256及冲突；向用户说明分类理由、需同步的索引/链接/配置、停用旧入口与恢复方式。文件多时展示按批次汇总和代表例，同时提供完整映射，不以笼统“整理一下”代替范围。
3. 目标同名时先比对；不覆盖或自动去重，相同内容也不自行删除。无法判断归属、目标冲突、仍被其他任务写入、无法读取的文件保留并列待处理，不猜测放置。
4. 方案明确哪些是移动、哪些仅复制，是否移除验收后的旧副本；若需改正文中的链接，列出文件与差异，原始材料不改。对方同意具体方案后，Agent连续执行搬迁、入口修复和验收，不能只交一份建议便结束。范围及方案未变不逐文件重复问；新冲突仅暂停受影响项再咨询。

## 执行与核验

- 操作前比对来源与目标快照。发生变化则重读、更新受影响方案，不用旧快照覆盖新文件。确认原执行者停止写同一任务；不新增锁系统。
- 按任务整包保留相对路径，用平台提供的“目标存在即拒绝”移动/创建能力。同文件系统可采用不覆盖的重命名；跨文件系统先复制到不覆盖的新目标，逐件校验后才按已批准的移动范围移除旧副本。事前检查目标不存在不能替代实际写入时的不覆盖保证。
- 受批准的索引、导航、活动链接、路径配置与启动入口随迁移同步；改前保存副本，使用映射定向修改，不全局猜测替换。链接修订文件分别记录改前/改后哈希和差异；未修订内容与源哈希应一致。历史原件保留字节不变，必要的路径映射保存在治理记录中。
- 核对完整文件集合、大小、哈希、依赖路径、旧位置状态和新入口可读可用。目标库有原件基线时，按其流程先核对授权的移动差异再更新基线，并独立复验，不用重建掩盖丢失或内容变化。
- 不改写bootstrap旧安装记录冒充自动迁移成功。路径变化超出生成器升级能力时，按已批准方案人工适配实际规则、路径配置和检查工具，保留原安装记录及此次迁移映射；说明后续升级需按实际结构适配，不强行绕过配置冲突。
- 中断时保留已验证目标和未完成来源，记录完成/待处理项。恢复前核对现场；回退也用不覆盖方式，不能覆盖后来产生的文件。已归档但清理未获授权的旧副本保留。

完成回报包括实际迁移与保留数量、目标入口、核验结果及未完成项。仅生成方案、复制未验证、链接未修好或目标环境不可访问时，分别如实说明，不称全量迁移完成。
