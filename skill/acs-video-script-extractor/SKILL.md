# 本地视频逐字稿与文案提取器

当前版本 `v1.5`。

本 Skill 的目标不是“跑一次语音识别”，而是把本地音视频转成**可追溯、可复核、角色分明**的逐字稿与还原整理文案。

核心原则：

1. **Local First**：源文件默认不上传，执行链路优先本地完成。
2. **Dual ASR**：默认至少两个本地模型交叉识别，不能把单模型结果冒充双模型校对。
3. **Risk-first Review**：数字、日期、否定词、一侧缺文和专名候选优先复核。
4. **Evidence Boundary**：模型原始转写、校对逐字稿、还原整理稿、创作稿严格分层。
5. **No Guessing**：关键身份、数字、专名和事实无法确认时明确留待确认，不猜。

## 适用范围

适合：

- 本地 MP4 / MOV / M4V / MP3 / M4A / WAV 等音视频；
- 用户要求完整逐字稿、视频文案提取、字幕校对、访谈转写；
- 需要重点核对人名、机构名、数字、日期、英文和否定表达的内容。

不负责：

- 主动寻找、破解或下载网络视频；
- 默认上传飞书妙记或其他云端转写服务；
- 默认将结果写入 Obsidian / 第二大脑 / 其他知识库；
- 在来源交付尚未完成前直接做传播性改写；
- 对无法确认的关键内容自行补全。

用户只有网络链接时，应先通过用户允许的其他 ingest / 下载流程获得本地媒体，再进入本 Skill。

## 默认交付

用户没有另行限定时，同时交付：

### 机器产物

1. `source-probe.json` / `source-probe.md`；
2. 双模型原始转写 JSON 与带时间戳文本；
3. `review-points.json` / `review-points.md`；
4. 视频存在可见字幕且需要复核时的 `review-frames/`。

### 最终交付

1. `逐字稿-校对版.md`：尽量忠实保留原话，标明实质校正和待确认项；
2. `文案-还原整理版.md`：在不改变原意的前提下，删除明显口头停顿、无意义重复和拍摄口令，但不新增观点、不重排论证；
3. `待确认疑点.md`：只列仍未可靠解决、且会影响事实、身份或含义的疑点。

从用户已给的要求确定处理范围和稿件。只指定稿件时，转写范围仍默认是整份媒体。指定片段时，只处理并核验该片段，交付标明原片区间和时间戳口径。仅生成用户约定的稿件，双模型、来源和漏段核验仍适用。未单独交疑点清单时，在交付稿或回复中说明未确认项。

用户明确要求优化、压缩、拟标题或生成发布稿时，先核验相应范围的来源，再另建创作稿。按实际交付需要保存来源稿和派生稿。

输出优先使用用户明确指定的位置，其次使用当前任务已有的约定目录。没有约定时，在当前可写工作区为本次任务新建独立目录。调用脚本时显式传入输出目录。

## 必须遵守的边界

- 仅处理用户有权访问的本地文件。
- 源媒体只读，不覆盖、不改写。
- 执行阶段不自动联网安装依赖，不自动下载 Whisper 模型。
- 不因文件扩展名正确就假定媒体有效，必须先做预检。
- 双模型一致不等于事实正确。人名、机构名、地名、数字、日期、身份、引语和敏感评价仍需结合字幕、上下文或用户确认。
- 视频没有可见字幕、纯音频或画面不足以辨认时，依据音频和上下文继续校对，并说明字幕复核范围。关键疑点留待确认。
- 原始模型结果不可手工覆盖；人工校正写入单独的最终文档。
- 用户随后明确要求入库时，按目标知识库的现行规则和可用工具办理。

## 执行流程

### 1. 只读媒体预检

用户只要片段时，先确认起止点并按[片段处理方法](docs/quick-start.md#只处理指定片段)制作独立工作副本。预检、双模型、差异比较和抽帧均对同一工作副本执行。整份媒体和片段的记录分开保存。

运行媒体预检脚本。

```bash
python scripts/probe_media.py \
  "/absolute/path/video.mp4" \
  --output-dir "/absolute/path/output"
```

必须确认并记录：

- 绝对路径、文件名、扩展名、字节数、修改时间、SHA-256；
- 媒体时长；
- 音频轨、视频轨与主要编码；
- 媒体是否可被 ffprobe 正常读取；
- 是否存在视频轨，以及是否能看到成片字幕。

如果媒体预检失败，停止，不把后续结果宣称为完整转写。

### 2. 本地双模型转写

运行：

```bash
python scripts/transcribe_local.py \
  "/absolute/path/video.mp4" \
  --output-dir "/absolute/path/output"
```

默认：

- `faster-whisper`；
- `large-v3` + `medium`；
- 中文；
- CPU `int8`；
- VAD；
- `local_files_only=True`；
- `HF_HUB_OFFLINE=1`。

运行环境查找顺序：

1. 当前 Python；
2. `ACS_TRANSCRIBE_PYTHON` 指定的环境；
3. Skill / 仓库附近的 `.venv`；
4. PATH 中可用的 Python。

任何候选环境都不能静默联网安装依赖。模型未缓存时停止并说明。

已有manifest或raw产物的目录拒绝复跑；使用新批次目录。预检文件可与本批转写共用目录。

长视频转写应保留进度输出。单个模型完成后立即保存结果和 manifest；第二模型失败时，保留已完成产物，同时明确双模型流程未完成。

### 3. 生成差异检查点与风险分级

```bash
python scripts/compare_transcripts.py \
  "/absolute/path/output/raw-large-v3.json" \
  "/absolute/path/output/raw-medium.json" \
  --output-dir "/absolute/path/output"
```

差异至少检查：

- 数字 / 日期，包括小数点、正负号和百分号造成的含义差异；
- 否定词；
- 英文 / 专名候选；
- 一侧缺句、重复、截断；
- 普通文字差异；
- 结尾补录、插播和画面切换处是否漏段。

`review-points.json` 只是复核入口，不自动决定哪个模型正确。

### 4. 视频字幕画面复核

仅当存在视频轨且成片有可见字幕时执行：

```bash
python scripts/extract_review_frames.py \
  "/absolute/path/video.mp4" \
  "/absolute/path/output/review-points.json" \
  --output-dir "/absolute/path/output/review-frames"
```

默认最多选 30 个检查点，但选择策略是**风险优先**，不是简单截取前 30 个。要处理全部检查点可使用：

```bash
--max-points 0
```

抽帧先校验视频SHA-256与差异文件相符，拒绝缺哈希、路径型或重复检查点编号。输出目录须为空或不存在，不覆盖已有画面；manifest记录源哈希。

逐张查看字幕与画面。一个时间点字幕未完整出现时，检查同一检查点的前后帧。字幕本身也可能有错，因此仍须结合声音、上下文和用户确认。

纯音频或无字幕视频跳过此步骤，不把“未抽帧”视为失败。

### 5. 按约定编写交付稿

按[输出格式](references/output-format.md)选择对应模板。交付逐字稿、整理稿或疑点清单，以用户的明确要求为准。只做片段时注明原片区间，校正和疑点时间点注明相对于原片还是片段。

- 校对稿保留原叙述顺序和有意义的语气，不为了顺滑而改变立场。
- 还原整理稿只清理口头噪声、重复和拍摄口令；保留原事实边界、情绪、举例和论证关系。
- 实质校正必须能追溯到时间戳、字幕画面、上下文或用户确认。
- 无法确认的词使用明确占位，例如 `[人名待确认｜02:13]`，在约定稿件、疑点清单或交付说明中记录。
- 不要求把标点、普通断句和不改变含义的语气词调整全部写入“校正记录”。

### 6. 按约定验收

默认验收三份稿件：

```bash
python scripts/validate_outputs.py "/absolute/path/output"
```

只验收约定稿件时，传入 `--deliverables`，可选 `transcript`（逐字稿）、`clean`（整理稿）、`issues`（疑点清单）。例如只要校对逐字稿：

```bash
python scripts/validate_outputs.py "/absolute/path/output" --deliverables transcript
```

超过15秒的头部、内部及尾部空缺均列为候选，同时报告双模型共同空缺；空缺不自动等于漏字。机器模式保留警告，完整验收须按 [空缺复核记录](references/coverage-review.md) 说明并给出依据，记录绑定当前原稿哈希。

默认验收和指定稿件验收都要求：

- 存在 `source-probe.json`；
- 至少两个不同模型的原始结果均存在且可解析，模型与结果文件不能重复登记；
- manifest、转写结果、probe 和 review points 均具有有效且一致的 SHA-256；
- raw与review时间戳不超出媒体时长（容许0.1秒舍入误差）；差异窗口以同目录probe时长裁切；
- 时间戳基本单调，媒体时长差异有明确警告；
- 已执行双模型差异比较；
- 约定的稿件均存在且非空，未限定交付时要求三份；
- 重要未确认项没有被写成确定事实。

脚本检查文件与数据结构；`PASS` 不替代人工核对语义、校正依据和待确认项。无差异时允许 `points: []`，但不能用空 JSON 对象代替完整的差异比较结果。

只想检查机器产物时可以使用：

```bash
python scripts/validate_outputs.py "/absolute/path/output" --machine-only
```

只有来源证据齐全、双模型校对完成、缺段已说明且约定稿件齐全时，才报告本次交付完成。

## 最终回复

向用户交付时至少说明：

- 是否完成双模型转写；
- 是否执行字幕画面复核，以及跳过原因（如有）；
- 实际处理的是全片还是指定区间，以及约定稿件的链接；
- 是否仍有待确认疑点；
- 是否存在完整性警告。

不要只说“已经提取好了”。
