# 常见问题

## 会把视频上传到云端吗？

默认不会。本 Skill 的转写、差异比较、抽帧和验收都设计为本地执行。

但你在准备 Python 包、FFmpeg 或 Whisper 模型时，可能需要自行联网下载安装。那属于环境准备，不是把源视频上传给第三方转写服务。

## 为什么一定要两个模型？

两个模型不是为了“投票决定真相”，而是为了暴露容易被单模型隐藏的差异。真正重要的差异还要结合字幕、声音、上下文或用户确认。

## 两个模型完全一致，就代表正确吗？

不代表。两套模型可能同时把同一个人名、机构名或数字听错，因此高风险事实仍需复核。

## 为什么默认是 `large-v3 + medium`？

这是该 Skill 的默认基线，用于制造足够强但不完全相同的识别结果。用户可以通过 `--models` 改成其他已经缓存的本地模型，但至少需要两个。

## 一定要有 FFmpeg 吗？

完整流程建议有。`ffprobe` 用于媒体预检，`ffmpeg` 用于视频字幕画面抽帧。纯转写本身由 faster-whisper 处理，但缺少预检就不能按本 Skill 的完整标准验收。

## Apple Silicon 可以用吗？

默认参数是 CPU `int8`，目的是提供较通用的本地基线。用户如果已有适合自己的设备配置，可以通过脚本参数调整 `--device` 与 `--compute-type`。

## 为什么没有写死 WorkBuddy 路径？

公开 Skill 必须可移植。若某台机器的 `faster-whisper` 位于特定 Python 环境，使用 `ACS_TRANSCRIBE_PYTHON` 指定即可；FFmpeg / ffprobe 同理使用 `ACS_FFMPEG` 与 `ACS_FFPROBE`。

## 差异超过 30 个怎么办？

抽帧默认最多选 30 个检查点，但会先按风险分挑选，再恢复时间顺序抽帧。需要全部处理时使用 `--max-points 0`。

## 可以只交校对逐字稿吗？

可以。明确说“只交校对逐字稿”，并按 [Quick Start](quick-start.md#8-验收) 用 `--deliverables transcript` 验收。仍要完成本次范围的双模型和完整性复核，未确认的人名、数字等写在稿件或交付说明中。没有限定稿件时，默认另交整理稿和疑点清单。

## 能不能直接把结果写进第二大脑？

确认转写与校对结果后，可以另行要求入库。按目标知识库现有规则查重、合并和追踪来源。
