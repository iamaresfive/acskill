# 从话题到公众号成品：流程与Skill

这里展示一套可以复用的创作方式，以及现在可使用的三个工具。具体过程见[《公考乱世，正在收场》创作方法案例](https://qs4978dogu.feishu.cn/docx/QKNbdUiAWoPEp0xHZgKcv0VBnCc)。飞书链接沿原文档权限访问，本仓库不会替读者开通权限。

**案例过程与现行工具分开看。** 案例用于说明如何提出问题、整理材料和作出修改；下面的审核Skill是现在可用的方法，不表示2026年10月9日创作该文时已逐项调用过。不以阅读量、排名或“成功案例”代替方法说明。

| 步骤 | 工具或Skill | 用途 |
| --- | --- | --- |
| 1. 日常积累素材 | 自己的笔记或知识库；需要搭建时可用[知识库初始化](../skill/acs-knowledge-governance-bootstrap/README.md) | 留下原文、来源日期、自己的想法，写作前检索已有观察与案例 |
| 2. 提出观察 | 作者与AI讨论 | 先给真实观察、经历和初步立场，不只丢一个标题 |
| 3. 讨论主线 | [内容吸引力审核](../skill/acs-content-appeal-review/README.md) | 参考同平台、同类型的内容，找到读者愿意追问的问题，检查正文有没有兑现开头的承诺 |
| 4. 核对材料 | 按材料选择读取与搜索工具 | 区分观察、事实和推演，回到公告、原文或实际记录 |
| 5. 组织成稿 | 作者与AI共同起草 | 安排每一部分的任务，让案例服务完整主线 |
| 6. 审核修改 | [个人文章与口播稿审核](../skill/acs-content-review/README.md)；必要时补[吸引力审核](../skill/acs-content-appeal-review/README.md) | 核对事实和逻辑，对照作者原意与改前改后，检查观点有没有被改偏 |
| 7. 制作成品 | [公众号定稿发布包](../skill/acs-wechat-publish-pack/README.md) | 定稿后排版、制作封面配图、检查复制页与手机效果 |
| 8. 复盘沉淀 | 作者回看本次过程 | 保留有用的修改、原始材料和版本，形成下次能用的规则 |

## 怎么开始

平时积累灵感、思考、新闻、讨论和方法；写作前先检索自己的素材库，再补缺少的资料。把本文和自己的话题交给AI，说明目标读者和已有材料。尚未成稿先讨论主线；已经定稿则直接走发布包，不为套流程重新审稿。作者负责经历、观点和最终取舍，AI负责展开问题、整理材料、起草、审核和制作。

一篇稿不必做三份审核报告。吸引力审核看“读者为什么看”，内容审核看“事实、主线和表达是否站得住”，发布包解决“定稿能否直接使用”。

## 外部能力按需连接

- `lark-doc`、`lark-minutes`属于飞书工具，用于读取文档或妙记。使用自己环境中已有的连接与权限；可从[飞书开放平台](https://open.feishu.cn/)了解接口，不假定本仓库已提供这些Skill或账号权限。
- `imagegen`是可选生图能力，名称和调用方式随宿主而异；本仓库不打包平台内置Skill。若使用OpenAI图像接口，可参考[官方图像生成文档](https://platform.openai.com/docs/guides/image-generation)。没有生图能力时使用获授权的现有素材或明确说明限制。
- 浏览器渲染用于检查真实成品，不能以脚本通过代替视觉验收。

这三个公开Skill保留自身必需的参考文件、脚本和界面配置；没有附带私人文章、内部账号规则、客户信息或作者卡。吸引力审核的方法参考见其[来源说明](../skill/acs-content-appeal-review/references/calibration.md)，不是把第三方工具冒称为原创。
