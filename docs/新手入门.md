# acskill 新手入门

`acskill` 不是一个万能 Agent，而是一组按任务拆分的 Skills。

第一次使用不需要先研究 `SKILL.md`。先判断你现在要做的是哪类任务，然后把真实文件和真实目标交给 Agent。

## 先选哪个 Skill

| 你的任务 | 使用 |
| --- | --- |
| 管理 Obsidian / Markdown 第二大脑、查历史知识、资料入库、更新合并、做知识库体检 | `acs-second-brain-manager` |
| 从本地视频 / 音频提取逐字稿、校对字幕、进行还原文案整理 | `acs-video-script-extractor` |

如果一个任务跨两个 Skill，例如“先把采访视频转成逐字稿，再入库第二大脑”，应先完成视频来源交付，再调用第二大脑 Skill 入库。不要让一个 Skill 静默越界代替另一个 Skill。

# 一、第二大脑：`acs-second-brain-manager`

你可能已经有一个 Obsidian / Markdown 知识库，想让 AI 真正长期帮你管理，而不是每次重新读资料、重新总结一遍。

`acs-second-brain-manager` 的目标是让 Agent 在长期使用中持续维护一套**可追溯、可更新、可查询、不过度改写原有结构**的第二大脑。

## 第一次怎么用

如果你已经有知识库，直接输入：

```text
请使用 acs-second-brain-manager 接管这个知识库。
这是一个已有库，第一次先只读扫描，不要修改文件。
```

然后告诉 Agent 知识库在哪里，例如：

```text
我的知识库就是当前这个 Obsidian Vault。
```

或者提供本地目录：

```text
我的知识库目录是：/你的/知识库/路径
```

第一次接管不会直接整理或重构。

Skill 会先理解：

- 目录和主要业务域；
- Markdown 页面和命名习惯；
- `AGENTS.md`、README、索引或已有治理规则；
- `[[Wiki Link]]` / Markdown Link；
- 原始资料放在哪里；
- 项目、人物、机构、专题和归档怎样组织；
- 是否已经存在脚本、自动化或多 Agent 协作规则。

然后先给一份 **Knowledge Base Understanding Report**，说明：

```text
已经确认了什么；
推断出了什么；
哪里存在冲突；
哪里还不知道；
哪些现有规则建议继续沿用。
```

你确认或纠正后，再进入长期治理。

## 如果你还没有知识库

可以直接说：

```text
请使用 acs-second-brain-manager 帮我建立一个新知识库。
主要用于行业研究、人物机构资料和项目管理。
先给最小结构方案，不要直接创建。
```

Skill 会先理解用途和内容类型，再提出最小可用结构，不会默认复制开发者自己的目录，也不会一开始创建大量分类。

## 平时最常用的任务

### 查询以前的知识

```text
我以前怎么看加盟模式？
```

```text
我们之前对这个机构做过什么判断？
```

```text
这个人物和哪些机构有关？
```

这类查询默认只读。

### 把新资料入库

```text
把这份同行交流记录入库。
```

```text
这是一份新的行业报告，先判断应该更新旧页还是新建。
```

Agent 不会看到新资料就机械新建文件，而是判断：

| 动作 | 你可以怎么理解 |
| --- | --- |
| `UPDATE` | 更新已有知识 |
| `MERGE` | 合并进已有内容 |
| `CREATE` | 确实需要新建知识页 |
| `PENDING` | 有冲突，暂时待核 |
| `SOURCE_ONLY` | 只保留原始材料 |

默认会先把 Mutation Plan 给你看，确认后再执行。

### 更新已经变化的信息

```text
这个老师现在已经去了另一家机构，更新一下。
```

```text
之前写的是计划开 5 个点，现在最终只落地 3 个，按最终情况更新。
```

Skill 优先维护当前可用知识，不机械生成“最新情况2”“最终版”等重复页面。

### 检查冲突

```text
这条信息和我以前的记录有没有冲突？先不要写。
```

遇到关键身份、金额、日期、实体等冲突时，不会擅自选一个答案写进长期知识库。

### 给知识库做体检

```text
做一次知识库健康检查，只报告问题，不要自动修复。
```

会检查重复、断链、孤立页、索引遗漏、缺来源、状态矛盾、碎片化、过期快照和结构漂移等问题。

## 哪些事情不会擅自做

普通“帮我入库”不会顺带授权：

- 删除文件；
- 大规模移动或批量重命名；
- 重构一级目录；
- 大规模合并实体；
- 修改知识库治理规则；
- 擅自改变多 Agent 写入机制。

这些高风险操作需要单独确认。

# 二、本地视频文案：`acs-video-script-extractor`

如果你有本地 MP4、MOV、M4A、MP3 等文件，想把内容完整提取出来，又不想只依赖一次语音识别，可以使用这个 Skill。

它的默认流程是：

```text
媒体预检
→ 双模型离线转写
→ 差异对齐与风险分级
→ 有字幕时抽帧复核
→ 校对逐字稿
→ 还原文案整理
→ 待确认疑点
→ 完整验收
```

## 第一次怎么用

最简单直接说：

```text
请使用 acs-video-script-extractor 处理这个本地视频。
全程离线，先做双模型转写，再校对高风险差异；如果视频有可见字幕，结合字幕画面复核。
最后给我完整逐字稿、还原整理文案和待确认疑点。
```

然后提供本地文件。

默认不会：

- 把源视频上传飞书妙记或其他云端转写服务；
- 自动从网络链接下载视频；
- 自动把结果写进第二大脑；
- 为了让文案“更好看”而偷偷补观点、案例、数据或结论。

## 你会得到什么

机器阶段会保留：

```text
source-probe.json
run-manifest.json
raw-large-v3.json
raw-medium.json
review-points.json
review-frames/（视频有字幕且需要时）
```

最终会得到：

```text
逐字稿-校对版.md
文案-还原整理版.md
待确认疑点.md
```

三个文件角色不同：

- **校对逐字稿**：回答“原视频到底说了什么”；
- **还原整理稿**：回答“在不改变原意的前提下，去掉口头噪声后怎样更容易读”；
- **疑点清单**：回答“还有哪些关键地方不能可靠确定”。

如果你后面还要朋友圈稿、短视频口播优化、标题等，再在来源稿基础上另做创作版本。

## 为什么不是跑一次 Whisper 就结束

因为单模型最容易把这些地方悄悄听错：

- 人名；
- 机构名；
- 数字和日期；
- 英文专名；
- “会 / 不会”“有 / 没有”这类否定关系。

双模型的作用不是投票，而是把差异暴露出来。差异点会被风险分级，有成片字幕时再结合字幕画面检查。

## 环境准备

本机需要：

- Python；
- `faster-whisper`；
- FFmpeg / ffprobe；
- 已缓存的本地 Whisper 模型，默认 `large-v3` + `medium`。

Skill 执行时不会自动联网安装依赖或下载模型。

如果你只是使用 Agent，不需要记所有命令；环境细节见：

# 三、两个 Skill 串起来怎么用

例如你有一段行业访谈，希望最后进入第二大脑：

第一步：

```text
请用 acs-video-script-extractor 把这段访谈做成完整校对逐字稿和还原整理稿。
```

确认来源交付完成后，再说：

```text
请用 acs-second-brain-manager 把这次访谈入库。
先查重、检查和已有机构/人物/专题的冲突，再给 Mutation Plan。
```

这样职责是清楚的：

```text
视频 Skill 负责把“原始音视频”变成可靠来源；
第二大脑 Skill 负责把“可靠来源”变成长期可用知识。
```

## 最简单的开始方式

你不用记命令，只要把真实任务说清楚：

```text
我要管理这个已有知识库。
```

或者：

```text
我要把这个本地视频完整提取成逐字稿和文案。
```

Agent 应根据任务选择对应 Skill，并遵守各自边界。
