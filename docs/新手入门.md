# acskill 新手入门

你可能是第一次看到 `acskill`，或者已经有一个 Obsidian / Markdown 知识库，想让 AI 真正长期帮你管理，而不是每次重新读一遍资料、重新总结一遍。

`acskill` 当前正式维护的 Skill 是 `acs-second-brain-manager`：一个面向本地 Markdown / Obsidian 知识库的第二大脑管理与知识治理 Skill。

它不是单纯的“文件搜索器”，也不是把聊天记录不断追加进知识库。它会先理解你原来的目录、命名、双链、项目和资料习惯，再决定应该查询、更新、合并、新建、待核，还是只保留原始材料。

你不需要先学知识管理理论，也不需要把需求说得很专业。第一次使用时，只需要把真实知识库和真实任务交给 Agent。

## 第一次怎么用

如果你已经有知识库，直接告诉 Agent：

```text
请使用 acs-second-brain-manager 接管这个知识库。
这是一个已有库，第一次先只读扫描，不要修改文件。
```

然后告诉它知识库在哪里，例如：

```text
我的知识库就是当前这个 Obsidian Vault。
```

或者：

```text
我的知识库目录是：/你的/知识库/路径
```

第一次接管已有库时，Skill 会先做 Read-only Adaptive Scan，理解：

- 你的一级、二级目录；
- Markdown 页面和主要业务域；
- 是否已经有 `AGENTS.md`、README、索引或结构说明；
- 是否使用 `[[Wiki Link]]` 或 Markdown Link；
- 是否有原始资料区；
- 项目、人物、机构、专题和归档怎样组织；
- 是否已经存在脚本、自动化或多 Agent 协作规则。

然后它会先给你一份 **Knowledge Base Understanding Report**。

这份报告的目的不是立刻改库，而是告诉你：

```text
我确认看到了什么；
我推断出了什么；
哪里有冲突；
哪里还不知道；
哪些现有规则建议继续沿用。
```

你确认或纠正后，它才进入长期治理状态。

## 如果你还没有知识库

也可以让它从零开始，但不要直接要求它“帮我建一套最完整的第二大脑”。

更推荐这样说：

```text
我要新建一个知识库，主要管理公考行业研究、项目资料、人物机构和长期判断。
先给我最小可用结构，不要一次建太多目录。
```

Skill 会先理解你的用途和内容类型，再提出最小结构方案。

你确认之后才会创建目录和治理文件，不会默认套用开发者自己的知识库结构。

## 第一次之后，平时直接说人话就可以

你不需要记命令。

### 查询以前的知识

```text
我以前怎么看加盟模式？
```

```text
我们之前对这个机构做过什么判断？
```

```text
赵某和哪些机构有关系？
```

这类任务默认只读，不会因为“查了一次”就自动改知识库。

### 把新资料入库

```text
把这份同行交流记录入库。
```

```text
把这份会议纪要整理进第二大脑。
```

```text
这是一份新的行业报告，先判断应该更新旧页还是新建。
```

Skill 不会看到新资料就机械创建新文件，而是先在五种动作里判断：

| 动作 | 含义 | 常见情况 |
| --- | --- | --- |
| `UPDATE` | 更新已有知识 | 新事实已经替代旧状态 |
| `MERGE` | 合并进已有页面 | 新材料属于已经存在的主题 |
| `CREATE` | 新建知识页 | 出现新的实体、概念、项目、案例或流程 |
| `PENDING` | 暂时待核 | 关键身份、金额、日期或事实存在冲突 |
| `SOURCE_ONLY` | 只保存原始材料 | 原件值得留存，但当前没必要形成独立知识页 |

默认情况下，它会先把写入方案给你看，你确认后再执行。

### 更新已经变化的信息

```text
这个老师现在已经去了另一家机构，更新一下。
```

```text
这个项目已经确定暂停，把当前状态更新掉。
```

```text
之前写的是计划开 5 个点，现在最终只落地 3 个，按最终情况更新。
```

Skill 优先维护“当前可用知识”，不会机械新增：

```text
某老师最新情况.md
某老师最新情况2.md
某老师最新情况最终版.md
```

历史依据仍然由原始材料、来源记录或必要快照保留。

### 检查有没有冲突

```text
这条信息和我以前的判断有没有冲突？
```

```text
这两份资料里招生人数不一样，先别猜，帮我找冲突。
```

```text
检查一下这个人物是不是和库里另一个同名人物其实是同一个人。
```

Skill 会区分：

- 来源直接支持的事实；
- 用户自己的判断；
- Agent 的分析推断；
- 用户已经拍板的决策；
- 当前仍然未知或待核的信息。

它不会把“你觉得可能是这样”偷偷写成“事实就是这样”。

### 给知识库做体检

```text
做一次知识库健康检查，先只报告问题，不要修改。
```

检查会关注例如：

- 重复文件和疑似重复实体；
- 断链、孤立页；
- 索引遗漏；
- 重要事实缺少来源；
- 已经过期的时间快照；
- 项目状态互相矛盾；
- 同一个主题被拆得过碎；
- frontmatter、命名和路径规则发生漂移。

健康检查默认只报告，不自动修复。

## acs-second-brain-manager 怎样工作

一次典型任务大致是：

1. 先理解当前知识库规则和相关页面；
2. 找到真实来源与已有知识；
3. 检查重复、冲突、时效和实体关系；
4. 判断应该 `UPDATE / MERGE / CREATE / PENDING / SOURCE_ONLY`；
5. 在默认模式下先给 Mutation Plan；
6. 你确认后，在批准范围内完成写入；
7. 写完再检查索引、关系、项目状态和结果一致性；
8. 最后明确告诉你改了什么、还剩什么待核。

它的目标不是“多生成 Markdown”，而是让知识库里的当前知识越来越清楚、越来越容易继续使用。

## 为什么要把原始材料和知识页分开

这是整个 Skill 最重要的设计之一。

假设你拿到一份：

```text
某机构2026年内部交流纪要.docx
```

更推荐的结构是：

```text
原始材料/
└── 某机构2026年内部交流纪要.docx

知识页/
├── 机构-某机构.md
├── 公考机构渠道模式.md
└── 班型运营模式对比.md
```

原始材料解决的是：

> 当时到底说了什么？

知识页解决的是：

> 基于目前全部信息，我们现在对这件事到底怎么看？

以后判断变化，可以继续更新知识页，但原件仍然保留，方便追溯。

## 为什么不是每次聊天都写进知识库

第二大脑不是聊天记录仓库。

用户问一次问题，不代表这个问题值得永久入库；Agent 做一次推理，也不代表这个推理已经成为稳定知识。

只有当内容对未来查询、决策、项目推进或知识复用具有长期价值时，才值得进入知识层。

因此：

```text
查询 ≠ 写入
聊天 ≠ 知识
原始资料 ≠ 当前结论
Agent 推断 ≠ 来源事实
```

## 三种写入模式

### `read-only`

只查询、分析、诊断和给建议，不写入知识库。

适合第一次扫描、审计和健康检查。

### `confirm-first`

默认推荐。

流程是：

```text
分析 → 给完整写入方案 → 你确认 → 在批准范围内执行
```

不是每改一个文件都重新确认一次，而是对完整 Mutation Plan 确认一次。

### `trusted-task`

适合你已经非常熟悉这套治理逻辑，并且给了一个边界清晰的长期维护任务。

Agent 可以在已批准任务边界内连续维护，但删除、大规模移动、治理规则变化等高风险操作仍然不能自动执行。

## 哪些事情它不会擅自做

普通“帮我入库”不会顺带授权下面这些动作：

- 删除文件；
- 一级目录新增、删除或重命名；
- 大规模移动、批量重命名；
- 改变页面类型体系；
- 改变模板、索引机制或来源策略；
- 大规模合并实体；
- 修改知识库治理规则的含义；
- 擅自把单 Agent 改成多 Agent 写入。

这些属于治理层变更，需要单独说明影响、迁移范围和回滚方式，再由你明确确认。

## 最常用的 12 句话

刚开始可以直接复制下面这些话使用：

```text
1. 接管这个已有知识库，第一次只读扫描，不要修改。
2. 先看看这份资料应该放哪里，不要写。
3. 把这份资料入库。
4. 更新一下这个机构的信息。
5. 这条和我以前的观点有没有冲突？
6. 我以前怎么看这个问题？
7. 把这几份资料合并进现有知识，不要重复建页。
8. 这个人可能和库里的另一个名字是同一个人，先核对。
9. 这个数据有时效性，按观察日期保存。
10. 做一次知识库健康检查，只报告不要修。
11. 告诉我这次准备改哪些文件，我确认后再写。
12. 把这次更新完成后，再检查索引、关系和项目状态有没有遗漏。
```

## 一个完整例子

你拿到一份新的同行交流记录，可以直接说：

```text
把这份同行交流记录入库。
先找库里已经存在的相关机构、人物和专题页，检查重复与冲突。
原始材料保留，不要改写。
知识层优先更新和合并，只有确实出现新实体或新主题才新建。
写之前先把完整 Mutation Plan 给我看。
```

你通常会先得到类似结果：

```text
建议：
- 原始纪要：SOURCE_ONLY，保存到现有原始资料区
- 机构 A：UPDATE，更新当前直营网点数量
- 渠道模式：MERGE，补充一个新案例
- 某老师身份：PENDING，两份资料存在冲突
- 不建议新建“交流纪要总结.md”
```

你确认后，Agent 才会真正写入，并在完成后报告：

```text
更新了什么；
新建了什么；
合并了什么；
哪些旧结论被覆盖；
哪些信息仍然待核；
哪些材料只做原始留存；
索引、关系和项目状态是否同步完成。
```

## 当前 Skill

### `acs-second-brain-manager`｜第二大脑管理与知识治理

**什么时候用：** 你已经有 Markdown / Obsidian 知识库，希望 AI 长期管理查询、资料入库、更新合并、来源追踪、实体关系、项目状态和知识库健康。

**你可以这样说：**

```text
请接管我的第二大脑。先只读理解现有结构，给我一份 Knowledge Base Understanding Report。
```

**你会得到：** 对已有知识库结构的理解、明确的治理边界，以及后续可持续执行的查询和写入流程。
