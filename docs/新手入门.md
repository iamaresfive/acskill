# acskill 新手入门

你可能已经有一个 Obsidian / Markdown 知识库，想让 AI 真正长期帮你管理，而不是每次重新读资料、重新总结一遍。

`acskill` 当前正式维护的核心 Skill 是 `acs-second-brain-manager`：一个面向本地 Markdown / Obsidian 知识库的第二大脑管理与知识治理 Skill。

你不需要先学知识管理理论，也不需要记命令。**先把真实知识库和真实任务交给 Agent 即可。**

## 第一次怎么用

如果你已经有知识库，直接输入：

```text
请使用 acs-second-brain-manager 接管这个知识库。
这是一个已有库，第一次先只读扫描，不要修改文件。
```

然后告诉 Agent 知识库在哪里，例如：

```text
我的知识库就是当前这个 Obsidian Vault。
```

或者提供本地目录：

```text
我的知识库目录是：/你的/知识库/路径
```

第一次接管不会直接整理或重构。

Skill 会先理解：

- 目录和主要业务域；
- Markdown 页面和命名习惯；
- `AGENTS.md`、README、索引或已有治理规则；
- `[[Wiki Link]]` / Markdown Link；
- 原始资料放在哪里；
- 项目、人物、机构、专题和归档怎样组织；
- 是否已经存在脚本、自动化或多 Agent 协作规则。

然后先给你一份 **Knowledge Base Understanding Report**，说明：

```text
已经确认了什么；
推断出了什么；
哪里存在冲突；
哪里还不知道；
哪些现有规则建议继续沿用。
```

你确认或纠正后，再进入长期治理。

## 如果你还没有知识库

可以直接说：

```text
请使用 acs-second-brain-manager 帮我建立一个新知识库。
主要用于行业研究、人物机构资料和项目管理。
先给最小结构方案，不要直接创建。
```

Skill 会先理解用途和内容类型，再提出最小可用结构。

不会默认复制开发者自己的目录，也不会一开始就创建大量分类。

## 第一次之后怎么用

不需要记工具名，平时直接说真实任务即可。

### 查询以前的知识

```text
我以前怎么看加盟模式？
```

```text
我们之前对这个机构做过什么判断？
```

```text
这个人物和哪些机构有关？
```

这类查询默认只读。

### 把新资料入库

```text
把这份同行交流记录入库。
```

```text
这是一份新的行业报告，先判断应该更新旧页还是新建。
```

Agent 不会看到新资料就机械新建文件，而是判断：

| 动作 | 你可以怎么理解 |
| --- | --- |
| `UPDATE` | 更新已有知识 |
| `MERGE` | 合并进已有内容 |
| `CREATE` | 确实需要新建知识页 |
| `PENDING` | 有冲突，暂时待核 |
| `SOURCE_ONLY` | 只保留原始材料 |

默认会先把 Mutation Plan 给你看，确认后再执行。

### 更新已经变化的信息

```text
这个老师现在已经去了另一家机构，更新一下。
```

```text
之前写的是计划开 5 个点，现在最终只落地 3 个，按最终情况更新。
```

Skill 优先维护当前可用知识，不机械生成“最新情况2”“最终版”等重复页面。

### 检查冲突

```text
这条信息和我以前的记录有没有冲突？先不要写。
```

```text
这两份资料里的招生人数不一样，先别猜，帮我核对。
```

遇到关键身份、金额、日期、实体等冲突时，不会擅自选一个答案写进长期知识库。

### 给知识库做体检

```text
做一次知识库健康检查，只报告问题，不要自动修复。
```

会检查重复、断链、孤立页、索引遗漏、缺来源、状态矛盾、碎片化、过期快照和结构漂移等问题。

## acs-second-brain-manager 怎样工作

一次典型任务大致是：

1. 理解当前知识库规则和相关页面；
2. 找到真实来源和已有知识；
3. 检查重复、冲突、时效和实体关系；
4. 判断应该更新、合并、新建、待核还是只留原件；
5. 默认先给 Mutation Plan；
6. 你确认后，在批准范围内执行；
7. 检查索引、关系和项目状态是否需要同步；
8. 最后明确告诉你改了什么、还剩什么待核。

目标不是“多生成 Markdown”，而是让当前知识越来越清楚、越来越容易继续使用。

## 最常用的 10 句话

刚开始可以直接复制：

```text
1. 接管这个已有知识库，第一次只读扫描，不要修改。
2. 先看看这份资料应该放哪里，不要写。
3. 把这份资料入库。
4. 更新一下这个机构的信息。
5. 这条和我以前的观点有没有冲突？
6. 我以前怎么看这个问题？
7. 把这几份资料合并进现有知识，不要重复建页。
8. 这个人可能和库里的另一个名字是同一个人，先核对。
9. 做一次知识库健康检查，只报告不要修。
10. 告诉我这次准备改哪些文件，我确认后再写。
```

## 一个完整例子

假设你拿到一份新的同行交流记录，可以直接说：

```text
把这份同行交流记录入库。
先找库里已经存在的相关机构、人物和专题页，检查重复与冲突。
原始材料保留，不要改写。
知识层优先更新和合并，只有确实出现新实体或新主题才新建。
写之前先把完整 Mutation Plan 给我看。
```

你可能先得到：

```text
建议：
- 原始纪要：SOURCE_ONLY，保存到现有原始资料区
- 机构 A：UPDATE，更新当前直营网点数量
- 渠道模式：MERGE，补充一个新案例
- 某老师身份：PENDING，两份资料存在冲突
- 不建议新建“交流纪要总结.md”
```

你确认后，Agent 再真正写入，并在结束时说明更新、新建、合并、覆盖、待核和索引同步情况。

## 哪些事情不会擅自做

普通“帮我入库”不会顺带授权：

- 删除文件；
- 大规模移动或批量重命名；
- 重构一级目录；
- 大规模合并实体；
- 修改知识库治理规则；
- 擅自改变多 Agent 写入机制。

这些高风险操作需要单独确认。

## 当前 Skill

### `acs-second-brain-manager`｜第二大脑管理与知识治理

**什么时候用：** 你已经有 Markdown / Obsidian 知识库，希望 AI 长期处理查询、资料入库、更新合并、来源追踪、实体关系、项目状态和知识库健康。

**你可以这样说：**

```text
请接管我的第二大脑。先只读理解现有结构，给我一份 Knowledge Base Understanding Report。
```

**你会得到：** 对已有知识库结构的理解、明确的治理边界，以及后续可持续执行的查询和写入流程。
